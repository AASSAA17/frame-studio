# Состояние реализации

Проект развивается по `SPECIFICATION_RU.md`. Рабочий путь соединяет сайт, сервер, PostgreSQL, кабинет клиента и CRM; текущая итерация добавляет управление студией. Полная система из двадцати разделов исходного задания ещё не завершена. Исходный аудит и отдельно зафиксированная базовая проверка находятся в `STAGE_2_AUDIT.md`.

Файл `PhotoStudio_Stage_2_Continuation_RU.md` не найден в Downloads, Documents, Desktop и рабочем каталоге; запрошенный путь пока не получен. Объём этой итерации основан на явном сообщении пользователя и `SPECIFICATION_RU.md`. Сопоставить порядок зависимостей и дополнительные требования отсутствующего файла можно только после его получения.

## Управление студией

| Область | Реализовано в этой итерации |
| --- | --- |
| Настройки | Форма владельца: имя/город/контакты, IANA-зона, часы, шаг и минимум, буферы, удержание, предоплата, напоминания, версия и текст правил. Публичный сайт читает актуальные значения без пересборки. |
| Каталог | Создание, редактирование, публикация и архив залов, локаций, специалистов, оборудования и услуг. Текущие/будущие оформления с периодами, без пересечения опубликованных версий. |
| Доступность | Графики по дням недели, исключения на дату, технические закрытия, отсутствие специалиста, состояние отдельных единиц техники. Конфликтующие изменения возвращают список затронутых заказов и ничего не отменяют скрыто. |
| Клиенты | Поиск, отдельная контактная карточка, теги, заметки сотрудников, история заказов/операций и архив. Возможные дубли показываются без автоматического объединения и без привязки аккаунта по совпадению email. |
| Ручная бронь | Выбор клиента и источника, общие с сайтом расчёт и доступность, фиксация согласованных условий, тот же механизм резервирования. Повтор создания идемпотентен. |
| Сохранность | Старые снимки цены/правил/оформления не меняются. Изменения используют ревизии записей; архив сохраняет историю. Редактирование ресурсов и бронирование сериализуются общими блокировками. |
| Доступ | Настройки и основной каталог изменяет OWNER; ADMIN управляет доступностью, клиентами и бронями. Клиент и специалист не получают внутреннюю клиентскую базу. Отозванная роль применяется к существующей сессии при следующем запросе. |
| Подтверждение условий | Заказ сравнивает отпечаток расчёта: смена правил, предоплаты или оформления между просмотром и созданием возвращает `409` и требует повторного подтверждения. Нулевая стоимость/предоплата не создаёт удержание. |
| Формы | Ошибки `400/403/409`, сохранение введённых значений, загрузка/пустые списки, подтверждение архивирования и защита несохранённых изменений при переходе/назад. |

## Тестовый режим

- `FRAME STUDIO`, каталог и цены — демонстрационные. Контакты и отзывы реального бизнеса не придуманы.
- Интерьеры представлены авторскими SVG-иллюстрациями, а не фотографиями действующей студии.
- Тестовый платёж не списывает средства. Реальный банковский адаптер не подключён.
- Mailpit принимает локальные тестовые письма. Внешняя доставка почты не настроена.
- Две демолокации одного зала используются для проверки общего ресурса.

SMTP-обработчик использует устойчивые задания и одинаковый Message-ID при повторе. При сбое между принятием письма SMTP-сервером и записью результата возможна повторная отправка; строгая гарантия единственной доставки не заявляется. Успешный SMTP-вызов обозначает принятие сообщения, а не доставку адресату.

## Последующие этапы основной версии

Полный редактор страниц и публикации; портфолио/галереи/видео; фильтр по доступности на дату и оборудованию; пакеты, промокоды и гибкие тарифы по времени/дням; CRM-воронка и предложения; полноценное производство и согласование контента; приватные загрузки, версии и сроки хранения; полный набор уведомлений; финансовая аналитика по периодам и ресурсам; процессы выгрузки/удаления персональных данных; реальные платёжные и коммуникационные адаптеры.

Создание профиля специалиста в каталоге не создаёт ему аккаунт и не назначает роль: интерфейс приглашения/привязки аккаунтов и управления ролями команды остаётся отдельной работой. Для клиента доступны подсказки возможных дублей; ручное объединение карточек с переносом истории ещё не реализовано.

Основные элементы интерфейса переведены на RU/KK. Перевод всех данных каталога, серверных сообщений, писем и юридических шаблонов требует отдельной редакторской проверки. Редактор переводов ещё не реализован. SEO-описания по каждой локации, sitemap и расширенная проверка доступности также остаются отдельной работой.
