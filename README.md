# FRAME STUDIO

Сайт и CRM фотостудии: каталог, бронирование с проверкой ресурсов в PostgreSQL, личный кабинет и управление студией. Владелец редактирует настройки, залы, локации, оформления, команду, услуги и технику; сотрудники работают с расписаниями, клиентами и ручными бронями. Проект развивается по [исходному заданию](docs/SPECIFICATION_RU.md).

Это демонстрационная конфигурация одной студии в Астане. Название, специалисты, иллюстрации и цены — тестовые. Платёжный режим `test` не списывает реальные деньги. Полное покрытие задания и результаты проверки приведены в [STATUS.md](docs/STATUS.md).

## Технологии

Next.js App Router, React, TypeScript, Tailwind CSS, Prisma и PostgreSQL. Авторизация — Better Auth с подтверждением почты. Локальная инфраструктура — Docker Compose, Mailpit и MinIO. Версии пакетов зафиксированы в `package.json` и `pnpm-lock.yaml`.

## Локальный запуск

Нужны Node.js 24, pnpm 11.25.0 и запущенный Docker с Linux-контейнерами. Из корня проекта:

```powershell
pnpm install --frozen-lockfile
Copy-Item .env.example .env
```

В `.env` задайте случайный `BETTER_AUTH_SECRET`. Для генерации:

```powershell
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
```

Затем:

```powershell
docker compose up -d
pnpm db:generate
pnpm db:migrate
pnpm db:seed
pnpm dev
```

Откройте [http://localhost:3000](http://localhost:3000). Зарегистрируйтесь через интерфейс и откройте письмо подтверждения в [Mailpit](http://localhost:8025). Mailpit хранит тестовые письма локально; письма не доставляются во внешние ящики.

В отдельном терминале запустите обработчик уведомлений:

```powershell
pnpm worker
```

Для macOS/Linux вместо `Copy-Item` используйте `cp`. Приложение и обработчик запускаются с компьютера; база, почта и объектное хранилище работают в контейнерах. Не выполняйте `docker compose down -v`, если хотите сохранить локальные заказы: ключ `-v` удаляет тома.

## Windows без Docker

Для текущей версии Docker необязателен. Если Docker Desktop не запускается, можно использовать установленные PostgreSQL 18 и PowerShell 7:

```powershell
pnpm install --frozen-lockfile
pwsh -File scripts/local-services.ps1 start
pnpm db:generate
pnpm db:migrate
pnpm db:seed
pnpm dev
```

Скрипт создаёт `.env` со случайным секретом, если файла ещё нет; запускает отдельную локальную базу и Mailpit; не меняет системную службу PostgreSQL. Данные находятся в исключённом из Git каталоге `work/services`. Если `.env` уже существует, заполните в нём `BETTER_AUTH_SECRET` самостоятельно. Для другого пути PostgreSQL укажите `-PostgresBin 'D:\PostgreSQL\18\bin'`.

Mailpit загружается из официального релиза с проверкой SHA-256. MinIO в этом варианте не запускается: приватные загрузки ещё не включены в первый этап. Не запускайте одновременно Docker-вариант и этот вариант на одних портах. Остановка с сохранением данных:

```powershell
pwsh -File scripts/local-services.ps1 stop
```

## Доступ владельца

В `.env` заполните `ADMIN_EMAIL`, `ADMIN_PASSWORD` (не менее 16 символов) и `ADMIN_NAME`, затем выполните:

```powershell
pnpm admin:create
```

Это отдельная команда начальной настройки, а не публичный способ повысить роль. После создания владельца удалите `ADMIN_PASSWORD` из файла окружения. Готового пароля администратора в репозитории нет.

## Проверка

```powershell
pnpm typecheck
pnpm test:unit
pnpm test:integration
pnpm test:migration
pnpm build
pnpm test:e2e
```

Интеграционные проверки очищают отдельную базу из `TEST_DATABASE_URL` с суффиксом `_test`. Сквозные проверки используют ещё одну базу `E2E_DATABASE_URL` с суффиксом `_e2e`, отличную от основной и интеграционной. Если адрес E2E не указан, он выводится из `TEST_DATABASE_URL` заменой суффикса. Все тестовые базы должны быть локальными и содержать только синтетические данные.

`pnpm test:e2e` после сборки сам создаёт отсутствующую E2E-базу, применяет миграции/seed, запускает отдельный сервер на `http://localhost:3100` и останавливает его после проверки. PostgreSQL и Mailpit должны быть запущены. Тестовые владельцы создаются только в E2E-базе; рабочая база не используется. `pnpm test:migration` проверяет сохранность старого заказа, платежа, резервов и очереди при миграции 004 в отдельной временной базе.

На Windows тест использует уже установленный Google Chrome. На других системах требуется браузер Chromium для Playwright или `E2E_BROWSER_CHANNEL=chrome` / `msedge`. При необходимости его установки: `pnpm exec playwright install chromium`. Другой локальный адрес можно задать через `E2E_BASE_URL` и `E2E_MAILPIT_URL`. Тесты отказываются работать с внешним адресом приложения. Подробности и фактические результаты — в [STATUS.md](docs/STATUS.md).

## Устройство проекта

| Путь | Назначение |
| --- | --- |
| `src/app` | Публичные страницы, кабинет, CRM и маршруты API. |
| `src/components` | Интерфейс и формы. |
| `src/lib/domain` | Доступность, цены, транзакции бронирования и денежные операции. |
| `src/lib/studio` | Управление студией, версии изменений, конфликты и клиентская база. |
| `src/lib` | Соединение с базой, авторизация и общие серверные средства. |
| `prisma` | Схема, миграция и демонстрационный каталог. |
| `scripts` | Создание владельца и обработчик фоновых заданий. |
| `tests` | Модульные, интеграционные и сквозные проверки. |
| `docs` | Задание, архитектура, состояние проекта и эксплуатация. |

Daylight и Seasonal намеренно связаны с одним физическим залом. Занятие одной локации закрывает то же время для другой. Защита работает на сервере и в базе, а не только в форме выбора времени.
